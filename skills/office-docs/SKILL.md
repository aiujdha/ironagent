# Office docs

Use the bundled script to create a minimal `.docx`, `.xlsx`, and matching `.pdf` files without external packages.

This skill is intended for controlled workspace tasks where the environment does not have LibreOffice, Chromium, or third-party Python packages available.

## When to use

- The user asks for a Word file and a PDF version of the same content.
- The user asks for an Excel file and a PDF summary of the same table.
- You need a deterministic office-file smoke test inside the current workspace.

## Workflow

1. Pick or create a target directory inside the active workspace.
2. Run the bundled script with the desired output names and content.
3. Prefer `--stdout-json` for smoke runs so you get a machine-readable summary back in one command.
4. Verify the generated files exist before replying.

## Quick start

```bash
python3 {baseDir}/scripts/make_office_docs.py \
  --out-dir ./temp/office-smoke \
  --title "Office Smoke" \
  --body "Generated by IronAgent inside the container." \
  --stdout-json \
  --sheet-name "Summary" \
  --headers "Item,Status" \
  --row "Office Smoke,Done"
```

Defaults:

- Word output: `agent-word.docx`
- Word PDF output: `agent-word.pdf`
- Excel output: `agent-sheet.xlsx`
- Excel PDF output: `agent-sheet.pdf`

## Common variants

Different output names:

```bash
python3 {baseDir}/scripts/make_office_docs.py \
  --out-dir ./temp/customer-pack \
  --word-docx proposal.docx \
  --word-pdf proposal.pdf \
  --sheet-xlsx summary.xlsx \
  --sheet-pdf summary.pdf \
  --manifest-json ./temp/customer-pack/office-manifest.json
```

Multiple Excel rows:

```bash
python3 {baseDir}/scripts/make_office_docs.py \
  --out-dir ./temp/report \
  --headers "Item,Value" \
  --row "IronAgent,1" \
  --row "SmokeTest,2" \
  --row "Approved,3"
```

## Practical guidance

- Keep all outputs inside the current workspace unless the user explicitly asks otherwise.
- Prefer this skill over ad hoc inline Python when the task is simply “make office artifacts”.
- If the user only asks for one pair, it is fine to ignore the unused outputs by setting custom names and only returning the files they asked about.
- For demos or smoke tests, prefer `--stdout-json` or `--manifest-json` so the assistant can quote exact output paths and sizes from a structured summary instead of re-listing files manually.
- Always confirm the final file paths and sizes after generation when the result is part of a smoke test or demo.
