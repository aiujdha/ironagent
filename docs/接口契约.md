# IronAgent API 接口契约

本文档是 Go Gateway 对上游开放的唯一 northbound API 契约。实现、测试脚本和交付文档都必须以本文档为准。

## 1. 通用规则

- 鉴权：`GET /api/v1/health` 注册在鉴权中间件之外，无需任何凭证；其余接口都经过网关鉴权中间件。仅当部署配置 `GO_GATEWAY_PUBLIC_AUTH_DISABLED=true` 时，public 范围接口才可不带 `X-API-Key` 调用；该配置的代码默认值与当前部署 configmap 均为 `false`，即上游必须携带具有 `public` scope 的 `X-API-Key`，否则返回 `401 {"error":{"code":"unauthorized","message":"invalid api key"}}`。`X-Client-ID`、`X-Timestamp`、`X-Nonce`、`X-Signature` 仅在网关配置了 HMAC secret 时才要求。
- 上游不传 `assistant_id`。Gateway 只根据 `user_id` 查找已有用户绑定助手；不存在时返回 `400 {"error":{"code":"bad_request","message":"用户无可用助手，请在后台重新创建助手后再继续调用"}}`。用户与助手的创建和绑定必须在创建助手流程完成。
- 文件上传下载使用本文档中的 HTTP 文件接口，不使用 MCP。
- 未列入本文档的请求字段和响应字段都不是上游接口契约的一部分。
- 非 2xx 错误响应统一使用 `{"error":{"code":"...","message":"错误说明"}}` 结构；`message` 必须能直接说明调用方需要修正的问题（业务层错误为中文文案，鉴权层错误的 `message` 为英文）。`code` 与状态码对照：

| `code` | 状态码 | 场景 |
| --- | --- | --- |
| `unauthorized` | 401 | 缺少或无效的 `X-API-Key`，或 HMAC 校验失败 |
| `forbidden` | 403 | API key 缺少所需 scope，或访问不属于该用户的文件 |
| `bad_request` | 400 / 422 | 请求格式错误、缺少必填字段、包含文档外字段（400）；引用的 `file_id` 不存在（422） |
| `conflict` | 409 | 状态冲突，如取消已终态任务 |
| `payload_too_large` / `request_too_large` | 413 | 请求体超限（业务层 / 鉴权层） |
| `queue_full` | 429 | 任务队列已满 |
| `southbound_error` | 透传南向 4xx；南向 5xx 映射为 502 | 南向服务返回错误 |
| `internal_error` | 500 | 服务端错误 |
| `callback_unavailable`、`callback_enqueue_failed`、`task_activation_failed` | 503 | callback 通道或任务队列暂不可用，可稍后重试 |

| --- | --- | --- | --- |

## 3. `GET /api/v1/health`

按用户维度检查服务是否可接收任务。上游必须传 `user_id`，Gateway 会先根据该用户查找已绑定助手，再检查该助手 runtime 状态是否可用。

请求参数：

| 字段 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `user_id` | query | string | 是 | 用户标识，Gateway 据此查找该用户绑定助手并检查助手状态 |

响应字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `status` | string | 是 | 服务状态 |
| `components` | object | 是 | 核心组件状态 |
| `components.gateway` | string | 是 | 网关进程状态，`up` 或 `down` |
| `components.agent_runner` | string | 是 | 用户绑定助手运行状态，绑定助手状态为 `ready`、`running` 或 `healthy` 时为 `up`，否则为 `down` |
| `components.container_scheduler` | string | 是 | 容器调度服务状态，`up` 或 `down` |
| `components.file_service` | string | 是 | 文件服务状态，`up` 或 `down` |
| `message` | string | 否 | 仅 `unhealthy` 时返回，说明异常原因 |
| `timestamp` | string | 是 | ISO 8601 时间 |
| `assistant` | object | 是 | `user_id` 绑定到的助手状态摘要 |
| `assistant.assistant_id` | string | 是 | 用户绑定助手 ID |
| `assistant.status` | string | 是 | 用户绑定助手 runtime 状态 |

状态码：

| 状态码 | 含义 |
| --- | --- |
| `200 OK` | 服务可用，或全局组件处于 `degraded` 但仍可接收请求 |
| `400 Bad Request` | 缺少 `user_id`，或用户没有可用绑定助手 |
| `503 Service Unavailable` | 网关、用户绑定助手、容器调度或文件服务不可用 |

## 7. `POST /api/v1/chat`

提交用户消息到 IronAgent 执行。IronAgent 接收后返回 `task_id`，并在执行过程中主动推送状态到小熊猫状态接收接口。

请求体只允许下表字段。传入文档外字段时，Gateway 必须返回 `400 Bad Request`，不能创建任务。

请求字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `request_id` | string | 是 | 请求唯一标识，作为幂等键 |
| `user_id` | string | 是 | 用户标识，Gateway 据此查找已绑定助手 |
| `conversation_id` | string | 是 | 会话标识 |
| `message` | string | 是 | 用户消息内容 |
| `files` | string[] | 否 | 附件文件 ID 列表，来自文件上传接口返回的 `file_id`。Gateway 必须在接收任务前校验文件存在且归属于该 `user_id`；不存在返回 `422 Unprocessable Entity` |
| `requires_result_file` | boolean | 否 | 是否要求任务必须产出结果文件，默认 `false` |
| `timeout_seconds` | integer | 否 | 任务超时时间（秒）。不传或为 0 时使用服务端默认值（默认 600 秒，可由部署配置覆盖） |

响应字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `task_id` | string | 是 | 任务唯一标识 |
| `status` | string | 是 | 任务当前状态 |
| `stage` | string | 是 | 任务当前执行阶段 |
| `created_at` | string | 是 | 创建时间 |

状态码：

| 状态码 | 含义 |
| --- | --- |
| `202 Accepted` | 任务已接收 |
| `400 Bad Request` | 请求格式错误、缺少必填字段或包含文档外字段 |
| `403 Forbidden` | 文件不属于该用户 |
| `422 Unprocessable Entity` | 引用的 `file_id` 不存在 |

## 8. `GET /api/v1/tasks/{task_id}`

查询任务状态。该接口用于断线恢复、callback 丢失、状态校准等兜底补偿。响应字段与 callback 推送的业务字段保持一致。

请求参数：

| 字段 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `task_id` | path | string | 是 | 任务唯一标识 |

响应字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `taskId` | string | 是 | 任务唯一标识 |
| `status` | string | 是 | 任务当前状态 |
| `stage` | string | 是 | 任务当前执行阶段 |
| `replyText` | string | 是 | 任务执行结果文本，仅 `completed` 时有值；其他状态为空字符串 |
| `files` | object[] | 否 | 结果文件列表，仅 `completed` 时有值 |
| `files[].fileId` | string | 否 | 文件唯一标识 |
| `files[].fileName` | string | 否 | 文件名 |
| `files[].size` | string | 否 | 文件大小，单位字节 |
| `files[].mimeType` | string | 否 | 文件 MIME 类型 |
| `files[].download_url` | string | 否 | 文件下载地址（注意该字段为 snake_case） |
| `errorCode` | string | 否 | `failed`、超时、`cancelled` 等异常终态时有值 |
| `errorMessage` | string | 否 | `failed`、超时、`cancelled` 等异常终态时有值 |
| `errorLocation` | string | 否 | 错误归因位置，标识故障发生环节；无错误时省略 |
| `errorReason` | string | 否 | 失败、取消或拒绝原因 |

## 11. 状态推送

IronAgent 在任务执行过程中以 `POST` 方式主动推送状态到上游回调地址。推送目标由网关配置 `GO_GATEWAY_DEFAULT_CALLBACK_URL` 决定；当前部署默认指向 `http://ironagent-callback-receiver:8099/taskcallback`，对接小熊猫生产环境时配置为其状态接收接口 `/intelligent-assistant/h5/iron/taskcallback`。

回调请求体的业务字段（`taskId/status/stage/replyText/files[]/errorCode/errorMessage/errorLocation/errorReason`）与 `GET /api/v1/tasks/{task_id}` 的响应字段保持一致；在此之外，回调请求体还包含投递元数据字段 `eventId`、`eventSeq`、`eventType`、`timestamp`、`nonce`、`signature`，供接收方做去重、排序与验签。注意：callback 中的 `replyText` 是 markdown 包装版本——非 markdown 文本会被加上 `### 执行结果`、`### 执行失败`、`### 重试安排` 等标题；`GET /api/v1/tasks/{task_id}` 返回原始文本，两者字段一致但取值可能不同。

Gateway 不要求上游轮询 callback，也不要求上游返回 ACK body；上游 HTTP 2xx 即视为本次推送成功。推送失败时记录中文日志，包括时间、任务 ID、回调地址、HTTP 状态码、失败原因和响应摘要；`GET /api/v1/tasks/{task_id}` 仅作为 callback 丢失、超时或状态校准时的兜底补偿查询。
