# Go Gateway 状态机

本文档只描述对外任务状态和阶段。接口字段见 `接口契约.md`，事件含义见 `事件契约.md`。

## 1. 设计原则

Go Gateway 对外屏蔽 Python collaboration task 内部状态。

统一状态必须同时用于：

- `POST /api/v1/chat` 响应。
- `GET /api/v1/tasks/{task_id}` fallback 查询。
- callback 事件 body。
- 测试断言。

## 2. 外部状态

| 状态 | 含义 | 是否终态 |
| --- | --- | --- |
| `processing` | 任务已接受，正在排队、编排或执行。 | 否 |
| `retrying` | 排队投递失败，等待下一次重试。只出现在 `task.retrying` callback 事件中；fallback 查询期间对外仍为 `processing`。 | 否 |
| `pending_approval` | 任务等待人工或策略审批。 | 否 |
| `completed` | 任务成功完成。 | 是 |
| `rejected` | 审批或策略拒绝。 | 是 |
| `failed` | 任务执行失败。 | 是 |
| `timeout` | 任务超时。 | 是 |
| `cancelled` | 任务被取消。 | 是 |

## 3. 外部阶段

| 阶段 | 含义 |
| --- | --- |
| `queued` | 已入队，等待 worker 或 runtime。 |
| `tool_running` | runtime 或下游工具正在执行。进度回调（`task.progress`）未带阶段时默认使用该阶段。 |
| `retry_wait` | 排队投递失败，等待重试。只出现在 `task.retrying` callback 事件中。 |
| `waiting_approval` | 等待审批。 |
| `done` | 任务成功完成（仅 `completed` 对应该阶段）。 |
| `error` | 失败或超时。 |
| `blocked` | 任务被取消或被审批/策略拒绝（`cancelled`、`rejected` 的对外阶段）。 |

当前实现只会产出以上阶段。

## 4. 合法流转

| 当前状态 | 允许进入 |
| --- | --- |
| `processing/queued` | `processing/tool_running`、`retrying/retry_wait`、`pending_approval/waiting_approval`、`cancelled/blocked`、`failed/error` |
| `processing/tool_running` | `pending_approval/waiting_approval`、`retrying/retry_wait`、`completed/done`、`failed/error`、`timeout/error`、`cancelled/blocked` |
| `retrying/retry_wait` | `processing/tool_running`、`failed/error`（重试耗尽）、`cancelled/blocked` |
| `pending_approval/waiting_approval` | `processing/tool_running`、`rejected/blocked`、`cancelled/blocked`、`timeout/error` |
| 任一终态 | 不允许再改变 |

终态包括：

- `completed`
- `rejected`
- `failed`
- `timeout`
- `cancelled`

## 5. Southbound 映射口径

Python southbound 内部状态只能在 Gateway 内部映射。

示例映射：

| Southbound 状态 | Gateway 状态 | Gateway 阶段 |
| --- | --- | --- |
| `pending_claim` | `processing` | `queued` |
| `claimed` | `processing` | `queued` |
| `running` | `processing` | `tool_running` |
| `pending_approval` | `pending_approval` | `waiting_approval` |
| `completed` | `completed` | `done` |
| `failed` | `failed` | `error` |
| `expired` | `timeout` | `error` |
| `cancelled` | `cancelled` | `blocked` |
| `rejected`（含 approval `denied`） | `rejected` | `blocked` |

如果 southbound 返回未知状态，当前实现不做保守映射：

- 状态：原样透传给上游（`publicTaskStatus` default 分支）。
- 阶段：返回空字符串（`publicTaskStage` default 分支）。

## 6. Approval 规则

审批等待：

- 对外 `pending_approval/waiting_approval`。
- callback 事件为 `task.approval_required`。

审批允许：

- 对外回到 `processing/tool_running` 或后续真实阶段。
- callback 事件为 `task.approval_resolved`。
- 如果后续执行继续推进，可再发送 `task.progress`。

审批拒绝：

- 对外 `rejected/blocked`。
- callback 事件为 `task.rejected`。

## 7. Cancel 规则

取消请求成功后：

- 对外 `cancelled/blocked`。
- callback 事件为 `task.cancelled`。
- runtime in-flight 必须释放。
- 已进入终态的任务不应被重新推进。

如果取消与 worker 执行并发发生，最终状态以终态优先，且不得从 `cancelled` 回写成 `processing`。

## 8. Fallback 查询规则

`GET /api/v1/tasks/{task_id}` 只返回统一状态，不返回内部细节。

fallback 查询结果必须能解释：

- 当前是否仍在处理。
- 是否等待审批。
- 是否已经终态。
- 如果失败，失败原因是什么。
- 如果成功，结果文本和结果文件是什么。
