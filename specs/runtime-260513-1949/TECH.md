- 相关 runtime-state spec：`specs/runtime-260518-1025/{PRODUCT,TECH}.md`。该 spec 定义通用 observed state、freshness、saved/applied generation/hash 和多节点收敛规则。

## 影响范围

- Admin：能力策略编辑、受影响助手展示、重启/重新加载动作。
- Security Service：第一版保留审批检查和审计链路，不作为最终集中拦截点。
- Go Gateway：第一版不新增集中策略拦截控制路由。
- Assistant Runtime：本地工具清单、允许工具校验、重新加载/重启行为。
- Workspace：已安装 skills/plugins 可能提供工具表面。
- UI：admin 状态必须区分“已保存策略”和“runtime 已生效策略”。
- Deploy/Ops：重启行为、健康检查、回滚证据。

## 修改方案

- 第一版采用“重启后生效”的保守语义。
- 第一版由 runtime 按重启后加载的策略执行，不实现 Security Service 集中拦截。
- Admin 需要区分“策略已保存”和“runtime 已生效”。
- 后续如要做热更新，必须先补充 generation/hash 或等价证据。

## 方案变更

### 接口

- 定义策略更新响应是否包含受影响助手 ID。
- 定义 admin 重启/重新加载动作复用现有助手重启接口，还是新增策略应用动作。
- 策略状态响应不得暴露内部 runtime token 或 workspace 文件内容。

### 状态与持久化

- 能力策略仍然是已保存的事实源。
- 如果实现需要，增加明确的 runtime 生效信号，例如策略 generation、策略 hash 或 `restart_required`。
- 持久化记录策略编辑、应用和重启动作的审计事件。

### Runtime 语义

- 最小可接受实现：策略编辑立即保存，但运行中的容器必须重启后才视为已更新。
- 未来可以实现热更新，但必须有证据证明运行中的助手已经刷新策略和工具清单。
- 助手有活跃任务时，必须等待当前任务完成后再重启，不立即中断任务。

### Workspace 影响

- 如果已安装 skills/plugins 暴露工具，runtime 必须明确策略变化只是过滤工具，还是要求重新加载工具清单。
- 仅修改能力策略时，本 spec 不要求重新安装 skills/plugins。

### 权限与安全边界

- 只有授权管理员可以编辑能力策略，或将策略应用到运行中的助手。
- UI 不能成为唯一执行点。
- 第一版不把 Security Service 作为所有工具调用的最终安全闸门。
- 审计必须记录谁修改了策略、修改了什么、影响哪些助手，以及通过什么动作应用。

### 部署与回滚

- 如果选择“重启后生效”语义，回滚方式是恢复旧策略，并重新重启受影响助手。
- 如果后续加入热更新，回滚必须能禁用热更新并回到“重启后生效”语义。
- 健康检查必须同时验证已保存策略状态和运行中助手状态。

## 回滚方式

- 撤回配置：恢复修改前的能力策略内容。
- 容器动作：按受影响助手列表重新重启对应助手容器。
- 数据恢复：如新增 policy generation/hash，需要恢复到上一版本或标记旧版本重新生效。
- 回滚证据：admin 状态、容器状态、runtime 日志、审计记录和危险工具拒绝/允许结果。

## 风险与缓解

- 风险：admin UI 把“已保存策略”展示得像“已实际生效”。缓解：区分已保存状态和 runtime 生效状态。
- 风险：runtime 保留旧工具清单。缓解：在热更新有明确 generation/hash 证据前，要求重启后生效。
- 风险：第一版只依赖 runtime 执行，运行中旧容器在重启前仍可能保留旧上下文。缓解：admin 明确展示需重启状态，等待空闲后重启，并验证重启后工具策略结果。

## 后续事项

- 只有在“重启后生效”行为可靠后，再考虑真正热更新。
- 如果后续要让 Security Service 或 Gateway 成为最终集中拦截点，单独开新的 S3 spec。
