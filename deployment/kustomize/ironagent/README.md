# IronAgent Kubernetes Stack

This tree turns the current `ironagent` cluster into a repeatable Kustomize deployment instead of a one-off collection of hand-edited manifests.

## Overlays

- `base`: static workloads, services, template files, and the remaining security-service
  hotfix the cluster is currently relying on.
- `overlays/runtime-common`: current live-compatible runtime shape.
  It keeps the workload pinned to the configured runtime worker, retains the `hostAliases`, and preserves the privileged control-plane settings needed by the current containerd-based assistant runtime.
- `overlays/prod-nodeport`: exposes only Go Gateway on `30808`.
  `ironagent-gateway`, `admin`, and `security-service` remain internal services.
- `overlays/prod-single-entry-nodeport`: legacy alias for the same single-entry NodePort model.
  `ironagent-gateway`, `admin`, and `security-service` remain internal services; use this for single-entry validation after Runtime Proxy is enabled.
- `overlays/runtime-k8s-pvc`: K8s-native assistant runtime profile.
  It adds the `assistant-workspaces` PVC, control-plane RBAC, and PVC mounts needed for `IRON_AGENT_RUNTIME_BACKEND=kubernetes`.
- `overlays/prod-k8s-single-entry-nodeport`: validation overlay for the K8s-native runtime profile plus the single Go Gateway NodePort.
  It also includes the Redis HA validation shape: `redis-ha` StatefulSet, local PV-backed PVCs, and official Redis Sentinel at `redis-sentinel:26379`.
  Use it before replacing the current containerd runtime in production.
- `overlays/prod-ingress`: recommended remote-access model.
  It keeps services internal and routes every public host to Go Gateway.

## Why this exists

The live cluster has drifted away from `deployment/*.yaml`:

- `security-service` currently depends on a patched `app.py`.
- the live Deployments also carry `hostPID`, `privileged`, `hostAliases`, and runtime-node pinning that were not fully expressed in the repo.

This Kustomize tree makes those requirements explicit so a future `kubectl apply` does not silently drop them.

## Current runtime assumptions

The stack is still running in a transitional architecture:

- all core workloads currently run on one configured runtime worker (`ironagent-worker` in the example manifests)
- the control plane talks to `containerd` through `/run/containerd/containerd.sock`
- `admin` and `security-service` launch assistant runtimes through `/app/ironagent/ironagent-feat-hooks/bin/ironagent-docker`
- that wrapper depends on host `/usr/local/bin/nerdctl` plus `/usr/bin/nsenter`
- assistant runtimes publish through the configured host port range instead of ad hoc containerd namespace defaults
- runtime state lives on host paths under `/app/ironagent`
- `go-gateway-secret` is intentionally not generated by `base`; create or update the real Secret before applying an overlay so placeholder values cannot overwrite production credentials
- `control-plane-shared-secret` carries Redis credentials for both Redis and Sentinel; preserve the live Secret before applying overlays with local placeholder env files

That means this stack is repeatable now, but it is not yet true multi-node high availability.

## K8s-native runtime validation

Use `prod-k8s-single-entry-nodeport` only when validating the PVC subPath runtime:

```bash
test -f deployment/kustomize/ironagent/overlays/prod-k8s-single-entry-nodeport/kustomization.yaml
kubectl kustomize deployment/kustomize/ironagent/overlays/prod-k8s-single-entry-nodeport \
  > /tmp/ironagent-prod-k8s-single-entry-nodeport.yaml
kubectl diff -f /tmp/ironagent-prod-k8s-single-entry-nodeport.yaml
```

If the `test` command fails or Kustomize reports `not a valid directory`, the
checkout does not contain the K8s runtime overlay. Do not continue from an older
checkout. Sync the latest `feat/go` branch or another commit that contains the
overlay first:

```bash
git fetch origin feat/go
git checkout feat/go
git pull --ff-only origin feat/go
test -f deployment/kustomize/ironagent/overlays/prod-k8s-single-entry-nodeport/kustomization.yaml
```

This overlay sets:

- `IRON_AGENT_RUNTIME_BACKEND=kubernetes`
- `IRON_AGENT_ASSISTANTS_WORKSPACE_ROOT=/workspace-root/assistants`
- `IRON_AGENT_ASSISTANTS_RUNTIME_ROOT=/workspace-root/runtime-state`
- `IRON_AGENT_K8S_RUNTIME_WORKSPACE_PVC=assistant-workspaces`

The K8s runtime profile creates one Pod and one Secret per assistant. It does
not create per-assistant NodePorts or Services by default; Go Gateway should
resolve assistant runtime addresses through the runtime registry.

The same profile also moves `ironagent-gateway` and `ironagent-cli` state from
hostPath to the shared PVC subPath `control-plane/ironagent-home`.

The `prod-k8s-single-entry-nodeport` validation overlay also includes a static
local PV bound to `vm-12-16-ubuntu` at `/app/ironagent/assistant-workspaces`.
Change that node/path before reusing the overlay on another cluster. For
multi-node production, replace it with an RWX StorageClass such as NAS/NFS/CephFS.

The same overlay deploys Redis as `redis-ha` with per-pod local PVs and three
official Redis Sentinel pods. Gateway should connect through Sentinel using
`GO_GATEWAY_REDIS_MODE=sentinel`,
`GO_GATEWAY_REDIS_SENTINEL_ADDRS=redis-sentinel:26379`, and
`GO_GATEWAY_REDIS_SENTINEL_MASTER=mymaster`. The compatibility `redis:6379`
service is not a master-aware write endpoint after failover.

## First rollout

1. Fill in the placeholders under the overlay you want to use.
   The committed files intentionally contain `REPLACE_ME`.
2. Ensure `control-plane-shared-secret` contains `IRON_AGENT_INTERNAL_SERVICE_TOKEN`,
   then create or update the real Go Gateway Secret before applying the overlay:

   ```bash
   kubectl -n ironagent create secret generic go-gateway-secret \
     --from-literal=GO_GATEWAY_DATABASE_URL='mysql+pymysql://<user>:<url-encoded-password>@<host>:<port>/<db>?charset=utf8mb4' \
     --from-literal=GO_GATEWAY_SCOPED_API_KEYS='public-key:public;runtime-key:runtime;debug-key:debug;admin-key:admin;proxy-key:proxy' \
     --from-literal=GO_GATEWAY_HMAC_SECRET='<hmac-secret>' \
     --from-literal=GO_GATEWAY_CALLBACK_SECRET='<callback-secret>' \
     --from-literal=GO_GATEWAY_PRESIGN_SECRET='<presign-secret>' \
     --from-literal=GO_GATEWAY_PROXY_SESSION_SECRET='<proxy-session-secret>' \
     --dry-run=client -o yaml | kubectl apply -f -
   ```

3. Render and diff the manifests.

   Single-entry NodePort validation should use the dedicated overlay:

   ```bash
   kubectl kustomize deployment/kustomize/ironagent/overlays/prod-single-entry-nodeport > /tmp/ironagent-prod-single-entry-nodeport.yaml
   kubectl diff -f /tmp/ironagent-prod-single-entry-nodeport.yaml
   ```

   HTTPS ingress validation should use the ingress overlay:

   ```bash
   kubectl kustomize deployment/kustomize/ironagent/overlays/prod-ingress > /tmp/ironagent-prod-ingress.yaml
   kubectl diff -f /tmp/ironagent-prod-ingress.yaml
   ```

   The default NodePort overlay also renders the same single public entry:

   ```bash
   kubectl kustomize deployment/kustomize/ironagent/overlays/prod-nodeport > /tmp/ironagent-prod-nodeport.yaml
   kubectl diff -f /tmp/ironagent-prod-nodeport.yaml
   ```

4. Before apply, fail fast if the source overlays or rendered manifests still contain placeholders:

   ```bash
   sh scripts/check_single_entry_exposure.sh

   if grep -R -E -n 'CHANGE_ME|REPLACE_ME' \
     deployment/kustomize/ironagent/overlays/prod-nodeport/config \
     deployment/kustomize/ironagent/overlays/prod-nodeport/secret; then
     echo 'overlay files still contain placeholders' >&2
     exit 1
   fi
   if grep -E -n 'v0\.0\.0-replace-me|registry\.example\.com' /tmp/ironagent-prod-nodeport.yaml; then
     echo 'rendered manifests still contain placeholders' >&2
     exit 1
   fi
   ```

5. Apply and wait for rollout:

   ```bash
   kubectl apply -f /tmp/ironagent-prod-nodeport.yaml
   kubectl -n ironagent rollout status deploy/go-gateway --timeout=300s
   kubectl -n ironagent rollout status deploy/admin --timeout=300s
   kubectl -n ironagent rollout status deploy/security-service --timeout=300s
   ```

6. Export the live state before any risky change:

   ```bash
   export IRON_AGENT_EXPORT_DIR="tmp/ironagent-live-$(date +%Y%m%d-%H%M%S)"
   mkdir -p "$IRON_AGENT_EXPORT_DIR"
   kubectl -n ironagent get all,cm,secret,ingress -o yaml > "$IRON_AGENT_EXPORT_DIR/ironagent-live.yaml"
   ```

## When to use each overlay

- `prod-nodeport`: preferred NodePort validation path when upstream should see only Go Gateway on `30808`.
- `prod-single-entry-nodeport`: compatibility alias for the same single-entry NodePort model.
- `prod-ingress`: the preferred target once an ingress controller and TLS certificate are ready.
  This is the path that aligns with the IronAgent Control UI security model and keeps public traffic on Go Gateway.

## Hotfix provenance

The following file was vendored from the live cluster on `2026-04-20` so it is no longer an implicit node-local dependency:

- `base/files/hotfix/security-service-app.py`

The historical `runtime-provisioner-hotfix` mount was removed. Runtime
provisioner changes must now be shipped by the admin/security-service image so
new images cannot be shadowed by a stale ConfigMap.

Emergency ConfigMap hotfixes are allowed only for short validation windows:

1. Apply the smallest possible ConfigMap override to verify the fix.
2. Commit the same source change to the branch immediately.
3. Build and deploy replacement images from that commit.
4. Remove the temporary hotfix volume, volumeMount, and ConfigMap.

Do not treat a live ConfigMap override as a release artifact. If a fix must
survive the next redeploy, it must be present in the image and the rendered
Kustomize manifest.
